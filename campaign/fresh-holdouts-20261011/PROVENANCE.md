# Private oracle provenance — successor set

Design owner: oracle_design. Read-only normative input: predecessor commit `6a7b5012494b090726c4184644cdaccbaba7837e`, `docs/design.md` and `docs/envelope.md`. No evolving repair implementation or regression-test files were inspected to select these cases. The previously disclosed H01–H06 cases are not reused as this set; the new cases vary observed mechanisms and evidence combinations, not just expected strings.

Q07 and Q09 contain an explicitly labeled command substitution. The informational line `EDAC amd64: Hardware accepted DRAM ECC Enable` is based on Linux v6.5 `amd64_enable_ecc_error_reporting` in [the primary tagged source](https://raw.githubusercontent.com/torvalds/linux/v6.5/drivers/edac/amd64_edac.c), lines3343–3350 in the retrieved representation. The function checks that the enable bit was accepted and emits `amd64_info` on success. This establishes configuration success, not a corrected or uncorrected memory event. The fixture adds a valid priority/timestamp representation and omits other kernel records deliberately; genuine raw guest logs are retained separately. No actual EDAC controller, real memory error, guest-generated message, or provenance authenticated by formatting is claimed. This differs from the previous successful-controller-registration template and tests configuration/capability vocabulary.

The same primary source's surrounding branch returns false when hardware rejects enabling, and the success line is reached when the configuration bit is present. That code path is sufficient for the finite informational-message oracle; it is not a catalogue of every EDAC driver or format. Source retrieval occurred2026-10-11 before candidate freeze.

TUN receive-drop generation reuses an already independently validated environmental helper, not an Alibi regression oracle. Q09 is a new joint case: actual sampled receive rejection together with benign initialization text and absent memory-controller evidence. Its verdict must be derived from independently overlapping counter samples; helper success never substitutes for actual induction. No physical-NIC or transport-loss equivalence is asserted.
