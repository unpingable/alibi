# Conservative v0.1 notes — unpublished draft

Release authorization is not granted by these notes. See QUALIFICATION.md for the final evidence-based disposition. The earlier campaign's HELD_DEFECT decision remains an immutable historical record.

Alibi interrogates one Linux host on demand and reports bounded findings for four named accusations. It performs no remediation or active network probes. CLEAR exonerates only the named accusation within the recorded evidence envelope; it does not declare a healthy host. UNKNOWN means the required evidence did not establish innocence. Supported positive evidence can justify DEGRADED while other sources remain unavailable, and those limitations must remain visible.

This repair changes three narrow behaviors:

- Network counter samples retain interface-directory and attribute descriptors, so a replacement interface cannot supply the second sample merely by reusing a name, MAC address or ifindex. Inadequate required samples prevent CLEAR.
- EDAC initialization text no longer implies a memory error. The recognized error grammar is deliberately narrow; ambiguous evidence prevents exoneration instead of inventing an interpretation.
- Default human output includes canonical source status, completeness, acquisition method, timing and material limitations. JSON Receipt V2 is unchanged.

The qualification environments are disposable QEMU TCG guests using retained Ubuntu Linux kernel images and a constructed GNU/Dash/BusyBox userspace. The full disclosed matrix uses 6.5.0-44-generic. The 6.8.0-90-generic evidence covers only the acquisition subset. This is not qualification of two complete distributions, physical hardware, arbitrary kernel versions or all Linux environments.

Network findings do not establish working DNS, endpoint reachability, application function, continuous namespace residence, every transient interface, hidden counter resets or an atomic snapshot. They require genuine sysfs attributes and coherent proc/sys views. EDAC interpretation fixtures are not actual hardware-error induction; VM absence of EDAC normally warrants UNKNOWN. Log acquisition does not authenticate substituted commands, prove freshness or recover overwritten history. Unsupported filesystems and inadequate evidence retain uncertainty.

Resource starvation, slow or stalled storage, general service functionality and the remaining qualification gaps are not silently added to the product's capabilities. The engineering campaign does not demonstrate reduced human diagnostic time. A separately designed operator comparison remains necessary before making that product-benefit claim.
