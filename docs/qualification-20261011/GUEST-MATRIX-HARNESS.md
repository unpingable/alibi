# Disclosed guest matrix harness

Owner/oracle designer: oracle_design. Execution/storage owner: campaign root. `campaign/guest-matrix.sh` is a guest-only scenario script, not a VM launcher. This lane performed **shell syntax validation only**, no boot/build/fault execution. The 38 disclosed IDs remain specifications until root records actual evidence. Final holdouts remain outside this script and undisclosed to implementation.

Each boot selects exactly one `alibi_case=Gxx` through runner `--case-id`. G02 requires `--isolated-nics 0`; other cases use one isolated NIC with no external backend. The script refuses absent campaign boot identity, wrong hostname, unexpected root (tmpfs normally, real overlay only for G22), non-root identity, or an existing occurrence directory. A selected-case baseline is collected before the fault. Root must use a fresh guest per case; a reused guest would contaminate retained kernel logs and invalidate baseline assumptions.

Current environment adaptation: independent Linux 6.5.0-44 kernel, supported tmpfs root, real proc/sysfs, GNU df/dmesg/ip plus BusyBox utilities. G01's original ext4-root control becomes an explicitly labeled tmpfs-root control; ext4-specific cases still require a guest-owned 32 MiB loop image. Root must not claim ext4-root boot coverage from an ext4 data mount. A second distribution/kernel remains a separate qualification gap.

The helper `/lib/alibi-lab.sh` captures stdout, stderr, invocation, monotonic offsets, exit status and GNU time resources into checksum-protected serial frames; `lab_run` returning zero means capture succeeded, not diagnosis passed. The matrix records raw kernel log, mountinfo, both route tables, interface statistics, capacity and inode statistics, EDAC presence, and conntrack presence before/after each invocation. The host runner must reject corrupt/missing frames. Per-case source/output hashes tie results to the actual archived scenario, binary and kernel.

Fault proof is separate from Alibi: capacity/inodes require independent statfs threshold checks plus failed writes/creates; read-only/bind cases show mount identities and actual write results; DNS/application cases capture independent client failure; application case must show HTTP500; route cases retain exact tables and flags. A successful setup command alone is not qualification. Deferred or unsuccessful setup prints F7. Conditional verdict labels reflect the predeclared matrix and must be adjudicated against raw evidence.

After explicit expanded guest-only admission, the successor script implements nft filtering, an independently gated veth drop-induction attempt and historical-counter control, conntrack pressure, actual overlay-root boot, XFS shutdown, dm-error under ext4, a private required-counter permission boundary, and an actual unmount before real df. Exact predeclared proof rules are in `guest-matrix-successor-spec.json` outside source custody. Cases remain unexecuted until root records results. G32 removes a veth during a nominal sample, but sleep timing alone proves nothing: reviewer must align independent transition timestamps to the receipt sample window. G33 repeats a stable critical-capacity case; repeats do not increase independent-scenario count.
